# Discord on Wayland and Hyprland

Research checked 30 October 2026. Package versions below refer to this checkout's lock, not necessarily the latest releases. Runtime behavior on these hosts has not been tested.

## Current configuration

- Desktop-enabled hosts select the default Nixpkgs Vesktop package, which manages its own Vencord files. Previously `wassaa` installed the official Nixpkgs Discord client with Vencord injected, while `tpad` had an OpenASAR override and a custom Discord launcher. See [desktop packages](../modules/core/features/desktop/packages.nix) and the [locked Vesktop package](https://github.com/NixOS/nixpkgs/blob/3ec636362e1816bc2f0888fa0fa2c69f1bc9e504/pkgs/by-name/ve/vesktop/package.nix).
- Hyprland sets `NIXOS_OZONE_WL=1` and enables XWayland. At the locked Nixpkgs revision, the Vesktop wrapper adds `--ozone-platform-hint=auto` when both `NIXOS_OZONE_WL` and `WAYLAND_DISPLAY` are set. This requests automatic backend selection; it does not prove which backend a running window uses. See the [Hyprland configuration](../modules/home/features/desktop/hyprland/hyprland.nix).
- The system enables PipeWire and uses Hyprland's portal with GTK fallback in Hyprland sessions. See [audio](../modules/core/features/audio/default.nix), [Hyprland](../modules/core/features/desktop/de-hyprland.nix), and [portal configuration](../modules/core/features/desktop/portals.nix). `wassaa` also enables optional [audio routing](../modules/core/features/multimedia/media-routing.nix); that is separate from application screen-share audio.

## Options

| Setup | Wayland and screen sharing | Trade-offs |
| --- | --- | --- |
| Official Discord, with or without Vencord | Portal-based screen sharing has been [reported working and failing](https://github.com/flathub/com.discordapp.Discord/issues/630) in different Linux setups; do not assume it always fails. The sources checked do not establish current official Linux stream-audio support. | Closest to the official desktop client. Vencord is a client modification, not Vesktop, so installing it does not automatically give Discord Vesktop's separate capture implementation. Vencord's authors say client modifications violate Discord's terms; enforcement is not guaranteed. [Vencord](https://github.com/Vencord/Vencord), [Vesktop capture implementation](https://github.com/Vencord/Vesktop/blob/main/src/main/screenShare.ts) |
| Vesktop | A custom Discord app with Vencord built in; the project advertises Linux Wayland screen sharing with sound. [Vesktop](https://github.com/Vencord/Vesktop) | A popular feature-oriented alternative, but its README lists global keybinds as unsupported. It is not official Discord. Capture can still break on specific setups; for example, an [open NixOS/niri report](https://github.com/Vencord/Vesktop/issues/1375) is not evidence that Hyprland has the same failure. The [locked Nixpkgs package](https://github.com/NixOS/nixpkgs/blob/3ec636362e1816bc2f0888fa0fa2c69f1bc9e504/pkgs/by-name/ve/vesktop/package.nix) is 1.6.8 and includes a Wayland-aware wrapper. |
| Equibop | A Vesktop fork with Equicord, also advertising Wayland sharing with sound. [Equibop](https://github.com/Equicord/Equibop) | Offers Linux command-line mic and deafen toggles that can be bound by the compositor. It is another modified, unofficial client; upstream lists the NixOS package as community-maintained. |
| Browser | Useful unmodified-client baseline for testing portal-based video sharing. Browser, Discord web app, portal and version all affect the result. | Do not assume Linux stream audio works merely because Chromium has implemented loopback capture. Verify audio separately. [Chromium implementation](https://github.com/chromium/chromium/commit/9a3d5ea818e66821c8a87b11b842dfd47c023608) |
| WebCord | An alternative wrapper around the web app, with similar web-client limitations. [WebCord features](https://github.com/SpacingBat3/WebCord/blob/master/docs/Features.md) | Its [audio discussion](https://github.com/SpacingBat3/WebCord/issues/154) does not establish that stream audio works in the current build. The project describes a [major rewrite](https://github.com/SpacingBat3/WebCord/blob/master/docs/Readme.md). |
| Flatpak | A packaging/sandbox choice for an app, not a separate Discord implementation or automatic Wayland/audio fix. Discord's [manifest](https://github.com/flathub/com.discordapp.Discord/blob/master/com.discordapp.Discord.yaml) grants Wayland, X11, PulseAudio and PipeWire access. | Vesktop documents file-access restrictions affecting drag-and-drop and limited game presence; granting broader access reduces isolation. [Flatpak notes](https://vesktop.dev/wiki/linux/flatpak/) |

## Suggested comparison

After deploying the change, test Vesktop's window backend, screen/window picker, received video, transmitted application audio, microphone, and the shortcuts you actually use. Test both a native Wayland window and any relevant XWayland application. Client rendering on Wayland and portal-based capture are separate questions; a missing or broken screencast portal can prevent sharing even when the window is native. [Vesktop troubleshooting](https://vesktop.dev/wiki/linux/troubleshooting/), [Hyprland portal](https://github.com/hyprwm/xdg-desktop-portal-hyprland).

Vesktop uses its own application data and Vencord settings. Expect to sign in again and check local plugin settings and themes; the old Discord data is not removed by changing the package. The Vesktop [roadmap](https://github.com/Vencord/Vesktop/issues/324) lists global keybinds as planned, without a promised order or date.

If shortcut control is important, compare Equibop's documented compositor-bindable toggles. If avoiding third-party client modifications matters more, compare the official client and the already configured Brave browser first. Keep video, stream audio and microphone routing separate in the test results.

Discord's own support and terms pages could not be retrieved during this research. The official client's current feature matrix and the actual behavior of this configuration remain unverified; Nix evaluation and builds were not run on this Windows checkout.
